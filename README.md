# 微信桌面助手（单群原型）

这个仓库探索如何让**现有 Codex 或其他 agent**通过本机 CLI，在一个明确绑定的普通微信测试群中读取并回复。当前范围仅限已授权的专用测试群；多群、MCP 服务、模型托管服务和客户群上线均不在本期。调用者负责生成回复，仓库没有模型提供方、API 密钥或联网推理代码。

目前代码包含本地单群绑定、受限的 Mac 桌面读取/发送驱动、SQLite 发送事务，以及一个离线的分页记录拼接器。Python 3.11/3.12 的合成测试覆盖这些模块；**本轮仓库 CLI 尚未在真实群完成读取或发送验收**。原生 `read` 和 `page` 只返回当前视口的 OCR 文字行，方向为 `unknown`。这些行不是已分出的消息，也没有微信官方消息 ID。离线记录器只能接收调用方已分好、已核验的气泡，尚未接到 CLI/OCR 读取链路，因此现阶段不能声称已经维护完整会话上下文。

另有本地 `parse-copy` 命令可解析调用者提供的复制文本，保留每条记录的显示发言者标签、分钟级显示时间、原文及顺序，结果明确标为**来源未核验、仅覆盖所提供副本**。用户手工选中的四条原文已核验；另一次依赖当次群身份确认的原生框选加复制取得五条测试原文，并通过 CLI 解析（选择范围、方向未验收）；自动框选、跨页复制与会话日志推进尚未实现。它不自行访问剪贴板或微信，也没有官方消息 ID；方向仍需视觉核对。

发送只开放显式合成测试。执行器必须核对前台窗口、精确标题、局部截图、AX 草稿及发送控件，先在磁盘记录一次尝试再点击。任何输入或点击结果不确定时都不自动重试。本机出现发送气泡只表示界面观察，收件端送达仍需独立证据。当前原生发送门禁尚未在本轮真实群证明可用。

另一次**仓库外的受监督 Computer Use 试跑**已在副屏识别准确测试群和空草稿，并将编号合成文本准确输入；一次 Return 后出现本人气泡及等待指示。手机登录确认后，原提交显示红色感叹号，另一测试身份确认未收到，故记录为**失败**。用户之后手动重发，同一编号气泡不再显示红色标志，但收件端尚未再次核验；这次人工动作只记录为本机界面观察。现已停止新发送及程序重试，仅做只读核验。登录提示与发送时间接近，尚无证据证明因果关系或自动化防御。[现场记录](docs/status.md)区分了程序失败和人工重试。

[单群 CLI 用法](docs/single-group-cli.md)说明配置、读取、分页和暂停；[架构](docs/architecture.md)、[计划](docs/plan.md)、[状态与证据](docs/status.md)及[安全边界](SECURITY.md)分别记录实现与未决条件。[单群架构图](.archify/architecture-single-group-channel-20261007-152801/single-group-channel.html)已通过自动门禁，并完成指定浅色截图的人工视觉检查；图示不构成真实桌面验收。

## 当前设计边界

- `channel_id` 是本地生成的单群 UUID；`account_binding_id` 是操作者配置的本地标签。两者都不是微信官方账号或聊天 ID，也不能仅凭配置证明当前登录身份。
- 原生读取在同一前台窗口的指定聊天区域进行。`read` 观察一屏；`page` 只在该区域滚动一次并观察新的一屏。没有连续历史、已读游标或订阅承诺。
- SQLite outbox 按调用方提供的稳定 `request_id` 防止重复派发；OCR 文本或图像指纹不能当成稳定消息身份。暂停/人工接手不抹掉已有尝试。
- 原生截图对象先在单个已核窗口内按区域裁剪，只对裁后图像取像素并做 OCR；不保存截图，也不回退全屏捕获。本地私有状态可以保留最小必要的配置、事务元数据及经确认的消息记录；这些运行数据不得发布到公开仓库。新路径在副屏取得正常标题像素和精确字面，但 OCR 置信度仍未通过门槛，未进入正文读取。

此前针对专用测试群的 Mac 试验曾读到合成消息，也记录过失败和不确定的发送。它们是本仓库设计输入，不能替代新 CLI 的现场验收；细节见[状态与证据](docs/status.md)。本仓库以 [MIT 许可证](LICENSE)发布。此前参考过的 [dustin573/wechat-mcp 固定提交](https://github.com/dustin573/wechat-mcp/tree/c6c600ae068c113224f984656db40f8cec4d0164)另有独立的静态审查；本仓库不复制其私有运行材料或把审查结论当作持续保证。
