MAC · 本地优先 · 可人工接管

让微信助手的每一步都可解释

目标是让你和独立助手账号在同一个群里，看得到回复，也随时能接手。本仓库先把读取、理解、执行和送达核验拆清楚，再逐步建设可运行的助手。

2026-10-07 设计基线：用户已另报告一次成功发送；稳定监听、完整三轮收发验收及客户群运行仍待验证。

现有试验路径

现在怎样操作微信

窗口与会话核对 → 区域截图 → 本机 OCR → 对话模型理解 → 受控输入与点击 → 本机画面和收件端核验。

解释此前试验中使用的技术；没有接通微信消息 API，也没有常驻模型服务。

最终怎样可靠协作

本机适配器持续观察指定会话，模型只给候选回复；确定性执行器检查目标与草稿，SQLite 记录尝试，人工控制台处理接管与未知结果。

模型提供方可替换；约课等业务由平台后端验证并执行。

打开目标架构图

推荐的技术组合

Python / PyObjC→AX / ScreenCaptureKit→本机 Apple Vision OCR→可替换模型接口→串行 UI 执行器 + SQLite

辅助功能能读到文字时优先使用；缺失时读取限定聊天区域的像素。视觉观察不提供官方消息 ID，点击和自己的气泡也不等于对方收到。发送结果未知时保留状态，不自动重发。

已实现的是离线发送状态库和合成模拟器。真实桌面驱动、持续监听、模型调用与操作员界面尚未接入。离线库核验调用方提供的观察，不能替代现场窗口与账号检查。

01

固定环境与只读适配

绑定唯一账号、窗口和测试会话；验证 AX / OCR、空帧停止、锁屏和窗口变化后的拒绝动作。

02

完成三轮真实收发

新请求、新编号、输入回读、一次点击和独立收件端确认；同时演练失败、未知结果与人工接管。

03

接入模型与操作员界面

先明确上下文传输范围，再接模型；显示候选、暂停、接手与发送证据，通过后进入小范围客户试点。
