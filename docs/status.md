# 证据与当前状态

更新时间：2026-10-07。本文件只给公开可分享的抽象结论。原始聊天、账号、群名、截图、测试编号和本机路径不随仓库发布。

## 已观察到的 Mac 试验

- 固定版本的第三方 Mac 微信 MCP 仓库曾完成 8 个 Python 源文件及项目文件的静态审查，许可证标为 MIT。未见自有源码主动外传聊天或窃取凭据的证据；不能由静态阅读保证绝对安全，依赖也未逐行全审。
- 指定测试群的三条合成请求曾通过窗口限定截图和 Apple Vision 本地 OCR 读取。原版辅助功能消息树在部分时段缺少聊天控件，重启后也曾短暂恢复再失效。截图原始空帧时，试验入口拒绝继续。
- 当前对话模型曾根据合成请求生成候选回复；没有独立模型服务或后台监听器。
- 一次已编号的新发送在准确输入并点击发送按钮后出现失败标志，另一测试身份确认未收到。另一次输入调用后截图失效，草稿是否存在未知，没有点击发送。它们分别保持“失败”和“未知”，不会因后续用户反馈而改写。
- 2026-10-07 用户另外报告过成功发送；目前没有足以关联到上述失败或未知事务的编号与送达证据，因此只记为单独的用户报告。更早一次历史测试回复由用户及延迟 GUI 画面确认，但也不能替代新的三轮验收。
- 尝试前持久化、重复观察拒绝和暂停门禁在隔离试验中有证据；不代表对任意真实消息具备可靠去重或严格恰好一次发送。

## 尚未有的证据

稳定的微信消息 API、服务器消息 ID 与回执、长期运行、真实客户群收发、独立助手账号在客户群的生产配置、完整三轮新请求闭环、常驻模型、操作员界面及人工接手演练均未完成。企业微信智能机器人对普通微信外部客户群的适用范围也未明确。

本仓库已在 Python 3.11 和 3.12 分别实跑 `PYTHONPATH=src python3.11 -m unittest discover -s tests -v` 与对应的 `python3.12` 命令，离线状态库均为 13/13 通过；3.11 下的 `examples/offline_simulation.py` 也通过。项目要求 Python 3.11 及以上；本机默认 `python3` 是 3.10，不能将其作为支持版本的验证。模拟器只使用合成事件，没有接微信、UI、消息 API、模型或网络。现有 outbox 只校验调用方提供的观察绑定和新鲜度，不自己探测前台、账号或屏幕锁；`conversation_id` 也不是微信官方会话 ID。Mac 试验的既有结论只是设计输入，不是此仓库桌面适配器已经运行的证明。
