# 架构：本地优先的桌面助手

本文分清**已观察的试验路径**与**拟实现的产品架构**。截至 2026-10-07，仓库中的原生桌面驱动、模型调用、常驻监听和操作员界面仍未完成；不能把下述模块图当作已部署清单。[现有试验机制图](../.archify/architecture-current-mechanism-20261007-144533/current-mechanism.html)与[目标系统概念图](../.archify/architecture-target-system-20261007-144533/target-system.html)分别用于解释现状和方向，不是运行验收证据。

## 目标数据流

```text
已登录的专用微信桌面账号
    ↓ 精确窗口与会话身份检查
桌面读取适配器（AX 可用时优先；否则限定窗口截图 + 本地 OCR）
    ↓ 带来源、方向、时间和置信边界的观察记录
会话策略与人工接管状态 → 上下文组装 → 可替换模型适配器
    ↓ 候选回复，先经过操作者规则
SQLite outbox → 单账号串行 UI 执行者 → 微信输入与发送控件
    ↓ 界面气泡 / 另一测试身份确认等证据
送达状态与本地操作员视图
```

观察记录不是微信服务器事件。OCR 文字没有稳定消息 ID，发送后看到自己的气泡也不是服务器回执。现有离线库的 `conversation_id` 是调用方配置的绑定值，**并非微信提供的官方会话 ID**。模型选择、是否调用外部服务及具体业务规则留到独立阶段决定，目前不持有模型凭据，也没有默认外传会话内容的路径。

## 模块职责和边界

| 模块 | 计划职责 | 当前状态 |
| --- | --- | --- |
| 桌面适配器 | 用 PyObjC/AppKit、AX、Quartz 和 ScreenCaptureKit 核对窗口、读取限定区域、执行输入与点击 | 先前隔离试验验证部分步骤；本仓库真实驱动未实现 |
| 读取与判定 | AX 能读到消息时使用 AX；否则先核精确窗口与群标题，再取局部图交给本地 Apple Vision OCR；区分自己与他人发言 | 三条合成消息曾在测试群读到；任意消息去重和版本稳定性未证 |
| 账号执行器 | 同一微信账号只允许一个 UI owner；读、聚焦、输入、点击与回读都进入串行队列 | 计划中 |
| 策略与上下文 | 指定会话允许范围、暂停/接手、触发条件、去重和候选回复上下文 | 接口待定 |
| 模型适配器 | 可替换供应商；显式决定何时发送哪些最小内容 | 未选供应商、未联网接入 |
| 业务工具适配器 | 未来需要约课、改期或退款时调用平台后端；模型只提出意图，后端验证身份、权限、时区、并发、状态和账本 | 未实现；本仓库不写平台业务数据 |
| Outbox | SQLite 持久事务、尝试前落盘、异常恢复与人工检查 | 离线状态库与合成模拟器已实现，13 项离线测试通过；只核调用方观察的绑定、新鲜度与状态，不探测操作系统或微信 |
| 操作员界面 | 展示候选、暂停、接手、未知结果和本机健康状态 | 未实现 |
| 官方接口适配器 | 在适用范围确证后可选接入企业微信智能机器人 | 仅文档研究；外部客户群适用性未证 |

未来的可信桌面驱动必须在现场确认唯一前台微信窗口、账号、屏幕锁状态、精确会话、可用像素、无模态遮挡及草稿状态，再构造观察交给 outbox。现有离线库不能替它做这些系统检查。截屏全零或全透明、AX 控件缺失、会话标题变化、输入未能复核时立即拒绝后续发送。**不能因为某一路截图失败就扩大到全屏读取**，也不能扫描其他会话列表寻找“差不多”的目标。

## 发送状态与恢复

现有离线库的准确状态是 `prepared`、`draft_verified`、`submit_attempted`、`ui_observed`、`failed`、`indeterminate` 和 `recipient_confirmed`。`submit_once` 在调用者提供新鲜草稿观察后，先落盘 `submit_attempted`，再最多调用一次传入的点击驱动；点击驱动目前只有合成模拟。真实文字输入与输入后现场复核的实现尚未接入。一个账号一次只处理一个发送事务。崩溃或视觉证据消失后，历史尝试保持已消费，交给操作者判断，不静默自动重试。`ui_observed` 只代表调用方提交的本机画面证据，`recipient_confirmed` 依赖独立收件端证据；两者均不等同微信服务器回执。

即使 outbox 能抵御进程重启、重复触发和并发 UI 操作，也不能在没有官方消息 ID 与发送确认的前提下保证严格恰好一次。相同文本可能由不同人或同一人再次发送；不能把文字哈希当作永久消息 ID。重复观察还可能来自 OCR 误读、截屏顺序、账号切换和手动发送。目标是把不确定状态显式化，让操作者可接手。

## 截屏健康与人工接手

健康状态至少记录：当前账号绑定、微信前台与窗口身份、群标题是否精确、AX 树可用程度、截图原始像素有效性和最近一次失败阶段。连续空帧或窗口状态变化触发熔断，暂停本账号发送队列；恢复读取不自动清空未知事务。界面应能让操作者看到每个候选和证据级别、暂停自动回复、手动处理草稿与失败消息。当前只有上述需求，没有可用的操作员产品界面。

## 可选官方接口

企业微信[智能机器人长连接接口](https://developer.work.weixin.qq.com/document/path/101463)描述群 `@` 回调与向已知 `chatid` 推送。它与普通微信桌面账号是不同的身份和运行方式。官方公开资料尚未清楚证明这种机器人可加入同时含普通微信外部客户的群；必须先核实际添加入口及收发范围，再决定能否作为这一目标的适配器。不要把所有 BotID/Secret 接口一概说成“仅内部群”，也不要承诺当前已经接通。
