# 单群阶段计划与验收

本期只验证一个已授权的专用测试群，让现有 agent 通过本地 CLI 读取和回复。多群、MCP、新建模型服务及客户群上线不在当前验收范围。工程检查与真实群验证分开记录。

## 下一轮现场验收：三关

主线收敛为一个原生桌面执行器：限定窗口的图像负责核对目标、选区和操作结果；原生框选与本次复制取得正文；解析、分页重建和 SQLite 保存已确认的本地上下文；现有 agent 通过 CLI 消费记录、提供候选回复。Computer Use 留作诊断辅助，不依赖其目前不支持的聊天区鼠标动作。以下仍是待实现、待实测的目标，不是可用能力声明；手工导入仅作对照，不替代自动频道交付。

1. **持续观察。** 先在已确认测试群中建立正常窗口捕获基线，再核对静止、聚焦、滚动及重新定位后的窗口身份和有效画面。若必须重启微信，只做一次受控对照，先保留草稿并记录重新登录需求；不反复重启或继续第四组 OCR 参数调试。既有标题阈值没有统计校准，不能解释为正确率。用户当次确认只能作为显式受监督实验的来源证据，不能静默替代 CLI 自动核群。正常基线无法建立或最小操作序列又产生不可恢复空帧时，停止后两关，留下复现步骤。
2. **自动跨页原文采集与恢复。** 同一执行器完成限定消息区框选、复制、解析、滚动半屏和重叠接续；剪贴板必须来自本次复制，不能读取旧内容。用跨至少三屏的编号合成记录覆盖重复正文、不同发言人、同分钟、长消息、分页时新增消息与进程中断。与独立人工清单核对条数、顺序、显示发言者及正文；方向没有独立证据时仍为未知。查清已有的选四条却取得五条问题。只有范围已核、重叠唯一、没有未决缺口，才推进用户确认起点之后的本地游标；否则返回部分结果并停住。通过后再接现有 agent session。
3. **受控单次发送与独立收件。** 前两关通过后，核完整草稿、目标和按钮，使用经过验证的原生点击路径提交一次授权合成回复，回读本机气泡与失败标记，再取得另一测试身份的收件证据。不把此前失败的 Return 或人工重试当作程序成功。结果不确定就暂停，不自动重发。一次成功只是一条证据，随后还需少量有记录的重复试验和人工干预演练，才能评估单群稳定性。

离线测试、CI 与这三关分别记录。现场失败时先处理发生失败的关卡，不继续扩大多群、订阅或 agent 集成范围。

## 既有交付与验收状态

| 阶段 | 交付与验收 | 当前状态 |
| --- | --- | --- |
| A 离线底座 | 单群绑定、私有状态、账号串行锁、发送事务；重启、重复请求、暂停、未知结果回归 | 已实现且离线回归通过；Python 3.11/3.12 离线各 72 项通过 |
| B 限定读取 | 在唯一前台窗口只读取精确测试群；标题/像素/窗口失败时拒绝；`read`/`page` 留下时间、窗口和视口指纹 | 标题区诊断 `doctor` 已接 CLI；真实试跑在登录窗口门禁拒绝；群读取仍未验收 |
| C 会话重建 | 可靠分气泡、区分方向、检测边缘截断；人工确认起点；跨页唯一重叠和断档处理；重启后按本地事件游标恢复 | 复制原文解析、离线 Bubble 拼接与私有存储已有；自动采集和确认日志尚未接通，不能声称持久上下文已可用 |
| D 受控合成发送 | 在同一精确群核草稿/按钮/前台/锁屏，输入前与点击前持久化；发送后的本机画面及另一身份收件证据分别记录 | 代码与合成测试已有，真实发送门禁未验收；旧试验含失败和未知，不能据此宣布通过 |
| E 现有 agent 集成 | agent 明确提供稳定 request ID 和候选文本；只消费已确认的单群事件；暂停/人工接管、断档和结果未知时停发 | 未实现端到端；CLI 无模型生成或后台订阅 |

仓库原生路径下一步仍须对**当前代码**做现场门禁核验：窗口身份、标题、局部图像、OCR 行、分页后的同窗复核，以及输入/发送控件。另一路受监督 Computer Use 路径已在副屏核群、读到可见气泡与空草稿，并准确输入一条编号合成文本；一次 Return 后出现本人气泡与等待指示。手机登录确认后，原提交显示红色失败标志，另一身份明确反馈未收到，记录为失败。用户独立手动重发后，本机界面没有红色标志、时间改变，但另一身份尚未再次确认；该人工重试只能记为 `ui_observed`，不能算原提交成功。这些动作都不计入仓库原生/CLI 的验收。当前停止新发送与程序重试，仅做只读核验；账号退出/登录提示与发送接近尚不足以判定原因。

每次测试分别记录“准确输入”“提交动作”“本机气泡”“另一端收到”。手工选取后的四条原文复制和 CLI 解析已核对正文、时间及顺序；程序自动框选仍被 CUA 辅助功能错误阻断，跨页复制未验证。Computer Use 可用于短期受监督测试，持久 record/cursor/去重与单账号串行发送仍需实现；主副屏共享键鼠焦点，不能并行操作同一微信账号。

会话验收需覆盖跨三屏以上的不同内容与重复内容、分页时插入新消息、OCR 漂移、截断气泡、checkpoint 不可达、进程中断和用户确认起点后的恢复。只有每页连接唯一且无未决缺口时，才允许从该**本地起点**推进上下文；微信完整历史和服务器级完整性始终不能由桌面 OCR 自证。

最新只读核验：新的单窗捕获在副屏标题区域取得非黑像素、标题字面精确匹配；基线及三组参数对照的置信度仍不足既有门槛，未进入正文或鼠标操作。保留此限制，不把原文样本解析和标题识别合并成完整自动读取验收。

补充只读证据：监督下的原生鼠标框选加复制取得五条已知测试原文，并通过 CLI。选择范围预期与实际条数不一致、方向未核，来源依赖用户当次确认，因此不会接入已确认 transcript 或被标为自动频道验收。
